# 사진 없는 피드 카드 UI 설계

## 목적

피드 API가 사진 URL 없이 반환한 일기도 `/feed` 목록에서 자연스럽게 읽고 반응할 수 있도록 텍스트 중심 카드를 제공한다.

현재 피드 카드는 정사각형 사진을 핵심 영역으로 사용하며, 사진이 없으면 외부 placeholder URL을 대신 표시한다. 이 방식은 실제 일기 내용과 관계없는 이미지가 노출되고, 사용자가 사진이 없는 일기를 정상 콘텐츠가 아닌 오류 상태로 오해하게 만든다.

이번 설계는 사진이 없는 일기를 컴팩트 에디토리얼 카드로 표현해 본문을 바로 읽을 수 있게 하는 것이 목적이다. 사진이 있는 일기의 이미지·캐러셀 경험, 피드 조회와 정렬, 상세 모달, 좋아요·댓글, 친구 관계, API 응답 계약은 변경하지 않는다.

## 현재 구조

- `app/feed/page.tsx`는 `/feed` 라우트 진입점과 Suspense 경계를 담당한다.
- `components/feed/FeedClient.tsx`는 피드 목록, 정렬, cursor 기반 추가 조회, 상세 모달, 좋아요·댓글 상태를 소유한다.
- `components/feed/FeedCard.tsx`는 작성자 헤더, 정사각형 사진 또는 캐러셀, 좋아요·댓글, 한 줄 본문, 댓글 입력을 하나의 카드로 표현한다.
- `FeedDiary.imgUrls`는 피드에 표시할 사진 URL 목록이며 사진이 없는 일기는 빈 목록으로 전달될 수 있다.
- 현재 `FeedCard`는 표시할 사진 URL이 없으면 외부 placeholder URL을 사용하므로 사진 없는 일기도 정사각형 이미지 영역을 차지한다.
- 카드 본문은 기본 한 줄로 접히며 내용 길이가 일정 기준을 넘으면 `더 보기`로 펼칠 수 있다.

## 설계 결정

사진 유무에 따라 `FeedCard`의 주 콘텐츠 영역만 분기한다.

- 사진이 한 장 이상이면 현재 정사각형 이미지·캐러셀과 하단 한 줄 본문을 그대로 유지한다.
- 사진이 없으면 이미지 영역과 하단 중복 본문을 제거하고, 작성자 헤더 바로 아래에 컴팩트 에디토리얼 본문 영역을 표시한다.
- 작성자 헤더, 친구 액션, 좋아요·댓글 수, 댓글 입력 영역은 두 카드 유형이 동일하게 사용한다.
- 사진 없는 카드에서는 외부 placeholder 이미지나 빈 정사각형을 렌더링하지 않는다.

새 카드 컴포넌트를 별도로 만들거나 `FeedClient`가 카드 유형을 판별하지 않는다. 사진 유무와 카드 내부 표현은 피드 항목 하나를 책임지는 `FeedCard` 안에서 결정해 목록과 데이터 흐름을 유지한다.

## 기능 흐름

### 사진이 있는 일기

1. 사용자가 `/feed`에 진입하면 `FeedClient`가 기존 방식으로 피드 목록을 조회한다.
2. 사진 URL이 한 장 이상인 항목은 현재 이미지 또는 캐러셀 카드를 표시한다.
3. 이미지 클릭, 좌우 이동, 페이지 점, 본문 펼치기, 좋아요, 댓글 동작은 현재 흐름을 유지한다.

### 사진이 없는 일기

1. 피드 항목의 사진 URL 목록이 비어 있으면 사진 영역을 만들지 않는다.
2. 작성자 헤더 아래에 `오늘의 일기` 라벨과 본문을 표시한다.
3. 짧은 본문은 전문을 표시한다.
4. 다섯 줄을 넘는 본문은 다섯 줄까지만 표시하고 `더 보기`를 제공한다.
5. 사용자가 `더 보기`를 누르면 같은 카드 안에서 전문을 펼치며 좋아요·댓글 영역은 아래로 이동한다.
6. 본문 영역에서 일기 상세 보기를 선택하면 기존 `onContentClick` 흐름을 통해 데스크톱 상세 모달 또는 모바일 스토리 모달을 연다.
7. 좋아요, 댓글 조회·작성, 친구 액션은 사진이 있는 카드와 같은 상태 변경 흐름을 사용한다.

## 시각 규칙

- 카드의 전체 폭, 테두리, 모서리, 그림자, 작성자 헤더는 현재 `FeedCard`와 동일하게 유지한다.
- 사진 없는 본문 영역은 별도 이미지 배경이나 일러스트 없이 흰색 카드 표면을 사용한다.
- `오늘의 일기`는 작은 라벨과 노란색 점으로 표현해 본문과 작성자 헤더의 위계를 구분한다.
- 본문 글자 크기는 `15px`로 하고, 행간은 긴 한국어 문장을 읽기 편한 수준으로 유지한다.
- 본문은 기본 최대 다섯 줄이며 단어가 중간에서 과도하게 끊기지 않도록 한국어 줄바꿈을 고려한다.
- `더 보기`는 본문보다 작은 중립색 텍스트 버튼으로 표시한다.
- 사진 카드보다 전체 높이는 짧게 유지하되, 작성자·본문·반응 영역 사이의 패딩으로 독립된 일기 카드라는 인상을 유지한다.
- 라이트 모드와 다크 모드에서 기존 카드의 배경·경계 대비 규칙을 따른다.
- 모바일과 데스크톱 모두 같은 정보 순서를 사용하며 별도 모바일 전용 카드 유형을 만들지 않는다.

## 상호작용과 접근성

- `더 보기`는 실제 버튼으로 제공하고 현재 펼침 여부를 보조기기에 전달한다.
- 접힌 상태의 본문이 실제로 다섯 줄을 넘을 때만 `더 보기`를 표시한다.
- 본문을 펼친 뒤에는 전문을 유지하며 같은 카드에서 다시 축소하는 동작은 이번 범위에 포함하지 않는다.
- 본문 상세 보기 영역은 마우스뿐 아니라 키보드로도 접근할 수 있어야 하며, `더 보기` 조작이 상세 모달 열기로 전파되지 않게 한다.
- 사진 없는 카드에는 의미 없는 이미지 대체 텍스트, 빈 이미지 요소, 캐러셀 화살표, 페이지 점을 노출하지 않는다.
- 좋아요와 댓글 버튼의 기존 접근 가능한 이름과 포커스 순서는 유지한다.

## 아키텍처 흐름

`FeedClient`는 현재와 같이 `FeedDiary` 항목과 이벤트 콜백을 `FeedCard`에 전달한다. 사진 없는 항목을 따로 분류하거나 목록 상태를 복제하지 않는다.

`FeedCard`는 전달받은 사진 URL 목록을 기준으로 이미지형과 텍스트형 주 콘텐츠 영역 중 하나를 선택한다. 텍스트형에서 본문이 다섯 줄을 넘는지는 카드가 실제로 렌더링된 뒤 표시 폭을 기준으로 판단한다. 이 판단 결과와 펼침 여부는 각 카드의 로컬 상태로만 관리하며 React Query, Zustand, URL, API 요청에는 반영하지 않는다.

사용자가 본문 상세 보기, 좋아요, 댓글, 친구 액션을 실행하면 현재 전달된 콜백과 기존 API 흐름을 그대로 사용한다. 따라서 `FeedClient`, `lib/api/feed.ts`, `FeedDiary` 타입, 백엔드 계약에는 새 분기나 필드가 필요하지 않다.

대표 흐름은 다음과 같다.

`피드 API 응답 → FeedClient 목록 상태 → FeedCard 사진 유무 판별 → 이미지형 또는 텍스트형 표현`

`텍스트 펼침 → FeedCard 로컬 상태 변경 → 같은 카드 안에서 전문 표시`

`상세·좋아요·댓글 선택 → 기존 FeedClient 콜백 → 기존 상세 또는 API 흐름`

## 데이터와 상태

새 서버 데이터나 전역 상태는 추가하지 않는다.

- 카드 유형은 기존 `imgUrls`의 항목 존재 여부로 결정한다.
- 현재 이미지 인덱스는 사진이 있는 카드에서만 의미를 가지며 기존 상태를 유지한다.
- 텍스트가 다섯 줄을 넘는지 여부와 펼침 여부는 카드 로컬 상태로 관리한다.
- 좋아요 수, 좋아요 여부, 댓글 수, 친구 상태는 현재 `FeedClient`가 소유하고 갱신하는 흐름을 유지한다.
- 정렬 변경이나 새 페이지 조회로 카드가 교체되면 텍스트 펼침 상태도 해당 카드 생명주기와 함께 초기화된다.

## 런타임 경계

본문의 실제 줄 수 판별은 렌더링된 요소의 크기에 의존하므로 기존 `FeedClient`의 클라이언트 경계 안에서만 수행한다. 서버 페이지나 API 모듈에서 DOM 크기를 조회하지 않는다.

최초 렌더링과 카드 표시 폭 변경 후 접힌 본문의 실제 높이를 다시 확인해 `더 보기` 표시 여부를 맞춘다. 이 측정은 각 카드의 텍스트 표현에만 영향을 주며 전역 초기화나 네트워크 부수 효과를 만들지 않는다.

이번 변경은 인증 복구, SSE, FCM, PWA, 이미지 로딩 초기화 경계를 변경하지 않는다. 사진이 없는 경우 이미지 요청 자체를 만들지 않으며, 사진 URL이 있으나 이미지 로드가 실패하는 경우의 대체 UI는 기존 동작을 유지한다.

## 오류 및 예외 처리

- `imgUrls`가 빈 목록이면 정상적인 사진 없는 일기로 처리하고 오류 안내를 표시하지 않는다.
- 사진이 없을 때 외부 placeholder URL을 요청하지 않는다.
- 본문은 기존 데이터 계약상 비어 있지 않다고 가정하며, 이번 변경에서 빈 본문용 별도 상태를 추가하지 않는다.
- 사진 URL이 존재하지만 실제 이미지 로드가 실패하는 상황은 사진 없는 일기와 구분하며 이번 범위에서 변경하지 않는다.
- 본문 줄 수 측정이 아직 완료되지 않았거나 지원되지 않는 경우에도 본문 자체는 표시하고 카드의 좋아요·댓글 동작을 막지 않는다.
- 피드 조회, 상세 조회, 좋아요, 댓글 요청 실패 처리는 기존 오류 흐름을 유지한다.

## 영향 범위

### 수정 대상

- `components/feed/FeedCard.tsx`: 사진 유무에 따른 주 콘텐츠 분기, 텍스트형 본문 표현, 다섯 줄 접기와 펼침 상태를 담당한다.
- `components/feed/__tests__/FeedCard.test.tsx`: 사진 없는 카드 표현과 기존 사진 카드 회귀를 검증한다.

### 변경하지 않는 대상

- `components/feed/FeedClient.tsx`: 목록·정렬·상세·반응 상태의 소유권을 유지한다.
- `app/feed/page.tsx`: 라우트와 Suspense 구조를 유지한다.
- `lib/api/feed.ts`, `types/diary.ts`: API 요청과 `FeedDiary` 계약을 유지한다.
- 피드 스켈레톤: 로딩 중 실제 항목의 사진 유무를 알 수 없으므로 현재 이미지형 스켈레톤을 유지한다.

## 문서 영향

이번 변경은 기존 `/feed` 라우트 안의 카드 표현만 변경한다. 라우트 구조, 디렉터리 책임, API 응답 계약, 전역 상태 경계, 브라우저 초기화 위치, 검증 명령과 테스트 전략은 변경하지 않는다.

따라서 `ARCHITECTURE.md`, `docs/architecture/directory-map.md`, `docs/frontend/runtime-contracts.md`, `docs/architecture/runtime-boundaries.md`, `docs/frontend/testing-and-verification.md`의 정식 내용은 갱신하지 않는다. 이 문서는 `docs/superpowers/plans` 아래의 로컬 작업 산출물로 관리한다.

## 검증 기준

### 컴포넌트 테스트

- 사진 URL이 한 장 이상이면 기존 이미지와 캐러셀 영역이 표시되는지 확인한다.
- 사진 URL이 비어 있으면 이미지, placeholder URL, 캐러셀 조작 요소가 표시되지 않는지 확인한다.
- 사진 없는 카드에 `오늘의 일기` 라벨과 본문이 표시되는지 확인한다.
- 다섯 줄을 넘지 않는 본문에는 `더 보기`가 표시되지 않는지 확인한다.
- 다섯 줄을 넘는 본문에는 `더 보기`가 표시되고 선택 시 같은 카드 안에서 전문이 펼쳐지는지 확인한다.
- `더 보기` 선택이 상세 보기 동작으로 전파되지 않는지 확인한다.
- 사진 없는 본문에서 상세 보기 선택 시 기존 `onContentClick` 콜백이 호출되는지 확인한다.
- 사진 유무와 관계없이 좋아요, 댓글, 친구 액션과 익명 작성자 표현이 기존대로 유지되는지 확인한다.

### 정적 검증

- `npx tsc --noEmit`으로 사진 유무 분기와 로컬 상태의 타입 안정성을 확인한다.
- 관련 `FeedCard` 컴포넌트 테스트를 실행한다.
- `npm run test:run`으로 기존 피드 및 전체 컴포넌트 회귀를 확인한다.

### 수동 검증

- 모바일과 데스크톱 폭에서 사진 카드와 사진 없는 카드가 한 목록에 섞였을 때 카드 간격과 시각 위계가 자연스러운지 확인한다.
- 짧은 글, 정확히 다섯 줄에 가까운 글, 매우 긴 글에서 접힘과 `더 보기` 표시가 올바른지 확인한다.
- 본문 글자 크기가 `15px`로 보이고 긴 한국어 문장의 행간과 줄바꿈이 읽기 편한지 확인한다.
- 본문을 펼친 뒤 좋아요·댓글 영역과 다음 카드의 위치가 자연스럽게 이동하는지 확인한다.
- 라이트 모드와 다크 모드에서 라벨, 본문, 경계선의 대비를 확인한다.
- 사진 없는 카드를 표시할 때 브라우저 네트워크 패널에 placeholder 이미지 요청이 생성되지 않는지 확인한다.

## 완료 조건

- 사진 없는 일기가 오류 이미지 없이 텍스트 중심 카드로 피드에 표시된다.
- 사진 없는 카드 본문은 `15px`로 표시되고 기본 최대 다섯 줄을 유지한다.
- 긴 본문만 `더 보기`를 제공하며 같은 카드 안에서 전문을 펼친다.
- 작성자, 좋아요, 댓글, 친구 관계와 상세 보기의 기존 동작이 유지된다.
- 사진이 있는 카드의 이미지·캐러셀·본문 동작에 회귀가 없다.
- API, 공통 타입, 전역 상태, 라우트 구조에 새 계약을 추가하지 않는다.
- 관련 컴포넌트 테스트, 타입 검사, 전체 회귀 테스트와 수동 확인이 통과한다.
